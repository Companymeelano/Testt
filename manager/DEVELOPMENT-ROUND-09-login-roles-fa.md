# دور ۹ — رفع دقیق مشکل نقش ورود (Modir ویزیتور شناخته می‌شد؛ Admin بن‌بست «نقش تعریف نشده»)

درخواست: «چرا با پنل Modir و رمز 123 با عنوان ویزیتور وارد می‌شود، در حالی که باید مدیر
اصلی باشد؟ و چرا با نام‌کاربری Admin (از مدیران اصلی آتیران) با ارورِ نقشِ تعریف‌نشده
مواجه می‌شوم؟ با دقت بسیار بالا رفع کن.»

## ۱) ریشه‌یابی (سه ایراد واقعی در مسیر ورود)

| # | نشانه | ریشهٔ دقیق |
|---|---|---|
| ۱ | `Modir`/`123` ← «ویزیتور» | `LoginActivity` ابتدا `visitors` را چک می‌کند و `fetchVisitorUser` نقش را **همیشه VISITOR هاردکد** می‌کرد؛ هیچ شاهد نقشی از هویت سیستمی/نام کاربری گرفته نمی‌شد |
| ۲ | `Admin`/`1385` ← خطا | نقش فقط از `sys_users.role_id → Roles/role` خوانده می‌شد: اگر نام نقش خوانده نمی‌شد ← **خطای قفل‌کننده** (ورود اصلاً باز نمی‌شد)؛ اگر نام نقش ناشناخته بود ← `SELLER` که خودش **قفل** بود (`phaseOpen`) ← «نقش … هنوز در این نسخه فعال نشده» |
| ۳ | — | جدول نگاشت `userrole` (کاربر←نقش) اصلاً خوانده نمی‌شد؛ نام نقشِ روی خود `sys_users` هم بررسی نمی‌شد |

## ۲) رفع — زنجیرهٔ چندلایهٔ شواهد نقش (بدون حدس احراز هویت)

احراز هویت همچنان **فقط رمز واقعی آتیران** است؛ فقط **نگاشت نقش** اصلاح شد:

1. **نام نقش آتیران مقدم است** (تغییرناپذیر برای نقش‌های صریح):
   `role_id → Roles/role` ← (جدید) جدول `userrole` ← (جدید) ستون نام نقش روی `sys_users`.
2. **در نبود شاهد نقش**، نام‌کاربری‌های **کامل و استانداردِ مدیر** تشخیص داده می‌شوند:
   `Modir`، `Admin`، `administrator`، `sysadmin`، `modir_amel`… (با پسوند عددی مثل `admin2`) و «مدیر».
   **فقط نام کامل** — `modirnejad`، `modir_nejad`، `ali_modir`، `admin_helper` هرگز شامل نمی‌شوند
   (تلهٔ نام‌های خانوادگی مثل «مدیرنژاد» با تست قفل شد).
3. **مسیر `visitors`** همان قاعدهٔ نام‌کاربری را اعمال می‌کند: پنلِ `Modir` ← «مدیر مجموعه»؛
   **هر ویزیتور دیگر دقیقاً مثل قبل** فقط میزکار ویزیتورِ خودش (`sys_vis`) — ورود/میزکار ویزیتور دست‌نخورده.
4. **بن‌بست‌ها حذف شدند**: همهٔ ۸ نقش تعریف‌شدهٔ RoleStore باز هستند (مجموعهٔ آیتم‌های همان نقش،
   مرز دسترسی است)؛ نام نقشِ خوانده‌نشده دیگر ورود معتبر را نمی‌بندد و به پیش‌فرض مستند
   («فروشنده» — قابل تغییر توسط مدیر در «کاربران») می‌رسد.

## ۳) پوشش تست (ماندگار در CI)

|---|---|
| `AtiranUsernameRoleTest` (جدید، ۵ تست) | نام‌های کاملِ مدیر → ADMIN؛ نام‌های خانوادگی هرگز؛ نام نقشِ صریح همیشه مقدم؛ نبود شاهد ← نام کاربری ← پیش‌فرض |
| `AtiranAuthPhaseTest` (به‌روزشده) | همهٔ ۸ نقش باز؛ فقط رشته‌های غیرنقش مسدود |
