## ۱) تشخیص قطعی خطای رندر داشبورد

گزارش فنی ارسالی مسیر را دقیق مشخص می‌کند:

- `IllegalStateException` در `ViewGroup.addViewInner`
- منبع: `HomeScreen.secAlerts`، هنگام ساخت دوبارهٔ داشبورد در `HomeScreen:settle`
- ردیف هشدار ابتدا فرزند `rows` بود و کد همان View را مستقیماً به `alerts` اضافه می‌کرد؛ درحالی‌که هنوز والد قبلی‌اش را داشت. اندروید اجازهٔ داشتن دو والد برای یک View را نمی‌دهد.

**اصلاح:** پیش از افزودن هر ردیف به کارت، آن را با `removeViewAt(0)` از ظرف موقت جدا می‌کنیم. ترتیب، حاشیه‌ها و چیدمان ردیف‌ها حفظ شده‌اند. علت این رخداد، برخلاف گزارش دور قبل، اکنون با stack trace گوشی اثبات شده است.

## ۲) تشخیص و اصلاح خطای ورود `TRY_CONVERT`

`LoginActivity` پیش از جست‌وجوی کاربر عادی در `sys_users`، مسیر ورود ویزیتور را امتحان می‌کند. استعلام قبلی و پیوند `sys_vis` از `TRY_CONVERT` استفاده می‌کردند؛ سروری که این تابع را نمی‌شناسد همان‌جا خطا می‌دهد و مسیر ورود کاربر عادی هم فرصت اجرا پیدا نمی‌کند.

**اصلاح:** استعلام ورود ویزیتور اکنون با `CAST` سازگارتر و خواندن ستون‌ها در نوع اصلی انجام می‌شود؛ شناسه‌ها در برنامه به‌صورت امن بررسی می‌شوند و برای کلیدهای عددی، نوع واقعی ستون مبنای مقایسه است. خواندن رمز/وضعیت، بررسی یکتایی حساب و کنترل پیوند دسترسی حفظ شده‌اند؛ دسترسی یا نقش حدس زده نمی‌شود و رمز در گزارش فنی ثبت نمی‌شود.

**محدودیت سازگاری که باید شفاف بماند:** این دور `TRY_CONVERT` را از مسیر اولیهٔ ورود و پیوند ویزیتور حذف می‌کند، اما موتور گزارش‌ها و بعضی بخش‌های دادهٔ برنامه در نقاط دیگری نیز از آن استفاده می‌کند؛ مستندات پروژه SQL Server 2014 را مبنا می‌گیرند. متن خطا نشان می‌دهد سرور/سطح سازگاری این دیتابیس تابع را نمی‌شناسد (معمولاً SQL Server قدیمی‌تر از ۲۰۱۲)، ولی نسخهٔ دقیق از همین متن قابل تعیین نیست. بنابراین اگر سرور واقعاً قدیمی باشد، پس از ورود ممکن است بعضی گزارش‌ها یا داده‌های عملیاتی نیز به پشتیبانی جداگانه نیاز داشته باشند؛ این build روی دیتابیس زندهٔ فروشگاه آزمایش نشده است.
