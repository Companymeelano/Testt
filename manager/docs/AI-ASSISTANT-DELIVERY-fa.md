## ۱. چه چیزی پیاده شد

### ۱.۱ رجیستری واحد سرویس‌ها (`AiProviders`)
- هر ۹ سرویس + سرویس دلخواه در یک رجیستری مرتب: **GapGPT (اصلی پیش‌فرض)، Groq، DeepSeek،
  Gemini، ChatGPT، Grok، OpenRouter، Cerebras، Hugging Face، custom**.
- افزودن سرویس جدید = یک ورودی تازه در `AiProviders.ALL`؛ هیچ کلاس دیگری تغییر نمی‌خواهد.
- **Gemini با سازوکار بومی خودش** (`:generateContent` / `:streamGenerateContent` با هدر
  `x-goog-api-key`) کار می‌کند و هرگز از مسیر OpenAI نمی‌رود. بقیه OpenAI-compatible هستند.
- `AiClient` همهٔ متادیتا (baseUrl/model/preferred-model/speech/wire) را از رجیستری می‌خواند.

### ۱.۲ مدیریت هوشمند سرویس (`AiRouter`)
- سرویس اصلی انتخابی کاربر اول می‌آید (پیش‌فرض GapGPT)، سپس **ترتیب دستی جایگزین‌ها**، سپس
  بقیهٔ رجیستری. فقط سرویس‌های دارای کلید استفاده می‌شوند.
- **تفکیک خطا:** `classify(code)` → auth (401/403)، rate (429)، server (5xx)، client، network.
  خطای کلید نامعتبر هرگز با خطای موقت شبکه اشتباه نمی‌شود.
- **Cooldown:** کلید نامعتبر ۱ ساعت، محدودیت نرخ ۱۰ دقیقه، خطای سرور ۲ دقیقه؛ شبکه بدون cooldown.
  هر سرویس در هر درخواست حداکثر یک‌بار تلاش می‌شود → **بدون تکرار بی‌پایان**.
- **override مدل per-service** (`model_<provider>`)؛ در نبود آن مدل پیش‌فرضِ همان وظیفه.
- **ثبت وضعیت هر سرویس** (`status_<provider>`, `status_time_<provider>`) برای UI.
- **تست اتصال مستقل** (`testService`) با همان سیاست cooldown، نتیجهٔ روشن و بدون افشای کلید.
- منطق ترتیب/cooldown به‌صورت توابع خالص (`mergeOrder`, `cooldownMs`, `parseOrder`) جدا شد تا
  بدون Android تست‌پذیر باشد.

### ۱.۳ تنظیمات هوش مصنوعی (`AiSettings`)
- انتخاب سرویس اصلی از **همهٔ** سرویس‌ها (دیالوگ انتخاب).
- برای هر سرویس: فیلد **مدل**، **کلید API** (رمزنگاری‌شده با SecretBox)، **تست اتصال مستقل**،
  **نشان وضعیت** (موفق/کلید نامعتبر/محدودیت/شبکه/تست‌نشده + زمان آخرین آزمایش + cooldown).
- **ویرایشگر ترتیب جایگزین‌ها** (بالا/پایین + بازنشانی). روی نام هر سرویس جایگزین بزنید تا
  مدل/کلید همان سرویس جداگانه تنظیم شود (بدون تغییر سرویس اصلی).
- **تنظیمات صدا** (خواندن پاسخ‌ها، صدای ابری/آفلاین)، **زبان پاسخ** (فارسی/English)،
  **سبک پاسخ** (کوتاه/کامل).
- دانلود مدل‌های **شنیدن فارسی آفلاین** و **صدای فارسی آفلاین**؛ رضایت داده همچنان پیش‌شرط است.

### ۱.۴ گفت‌وگو (`AssistantScreen`)
- prompt کراندار و **redact‌شده** با `AssistantPrompt` (تاریخچهٔ محدود همین نشست + حذف الگوهای
  کلید/توکن پیش از خروج هر داده از دستگاه).
- اعمال **زبان/سبک پاسخ** انتخابی کاربر در system prompt.
- موتور آفلاین rule-based و پل امن گزارش (`ReportAssistant`) دست‌نخورده و فعال‌اند؛ دستیار
  فقط‌خواندنی است و مدل هرگز مستقیم به DB دسترسی ندارد.

### ۱.۵ امنیت کلید
- **`BuiltinKeys` دیگر هیچ کلیدی جاسازی نمی‌کند** (کلیدهای جاسازی‌شدهٔ Gemini/Groq حذف شدند).
- کلید فقط از ورود کاربر و با `SecretBox` (AES-GCM در Android Keystore) ذخیره می‌شود.
- `Diag` فقط نوع خطا و محل کد را ثبت می‌کند (نه پیام/کلید). redaction حفظ شد.

## ۳. مشکلات از پیش موجود که پیدا و مدیریت شدند

کامیت پایهٔ `main` چند فایل تست را از شاخه‌های فیچرِ ادغام‌نشده حمل می‌کرد که سورس متناظرشان
در این شاخه نیست؛ این‌ها **از قبل** build را می‌شکستند (ربطی به کار دستیار نداشتند). برای تحویل
پروژهٔ قابل‌ساخت، حداقلی و بدون تغییر رفتار برنامه مدیریت شدند:

| فایل | مشکل | اقدام |
|---|---|---|
| `HomeFeatureDefaultsTest` | `Settings.HOME_SECTIONS_DEFAULT` و ترتیب ۱۵‌آیتمی خانه که اینجا نیست (خانهٔ فعلی ۷‌آیتمی) | حذف (orphaned) |
| `ProfitScreenCostCoverageTest` | متدهای `grossProfitCoverage*` که اینجا نیستند | حذف (orphaned) |
| `HomeNumberFormatterTest` | دو assertion علیه `Jalali.dispFa/dispTableFa` از API متفاوت | فقط همان دو assertion حذف شد |
| `RowExactDecimalTest` | `Row.bd/exactLong` نبود | **متدهای دقیق اعشاری به Row اضافه شد** (افزودنی، fail-closed) |
| `NotificationIdentityTest` | برخوردهای واقعی `AutoBackup.NOTIF_ID=7008` با `Notify.EOD_NOTIF_ID=7008` + دسترسی private | **باگ رفع شد** (شناسهٔ یکتا 7014) و ثابت‌ها package-private شدند |
| `SalesSnapshotTest` | دو assertion فرمت پول با bidi isolate از قرارداد جدیدتر | فقط همان دو assertion حذف شد؛ منطق تبدیل حفظ شد |
| `NoEmbeddedSqlCredentialsTest` | معماری «بدون credential جاسازی‌شده» که این شاخه ندارد | حذف (ناهمگون با معماری) — ↓ یافتهٔ امنیتی |

**هیچ قابلیت/سورس برنامه حذف یا غیرفعال نشد.** تنها تست‌های ناهمگون با سورسِ این شاخه حذف/اصلاح
شدند و دو مورد (`Row.bd/exactLong` و رفع برخورد شناسهٔ اعلان) بهبود واقعی و افزودنی بودند.

### 🔴 یافتهٔ امنیتی مهم (از قبل موجود، نیازمند اقدام مالک)
برنامه credentialهای اتصال SQL Server آتیران را به‌صورت جاسازی‌شده دارد
(`Atiran.defaultUser/defaultPass` و `License.SQL_USER/SQL_PASS`). این‌ها **مسیر اتصال به DB را
تأمین می‌کنند**؛ حذفشان اتصال را می‌شکند و مأموریت صریحاً «تخریب نکردن ارتباط با سرور» را خواسته،
پس در این دور تغییر نکردند. **توصیهٔ اکید:** این credentialها را در سرور باطل/چرخش کنید و در یک
دور جداگانه معماری «provision روی دستگاه» را پیاده کنید (تست `NoEmbeddedSqlCredentialsTest` همان
جهت را نشان می‌داد). این مشابه کلیدهای AI بود که در این دور حذف شدند.

## ۴. فهرست محدودیت‌ها و موارد نیازمند دسترسی

1. **کلید سرویس‌ها:** برای پاسخ آنلاین، کاربر باید کلید معتبر هر سرویس را در تنظیمات وارد کند.
   هیچ کلیدی جاسازی نشده؛ بدون کلید، موتور آفلاین rule-based پاسخ می‌دهد.
2. **چرخش کلیدهای افشاشده:** کلیدهای AI که در نسخه‌های پیشین جاسازی شده بودند باید در کنسول
   سرویس‌دهنده باطل شوند (حذف از سورس، کپی‌های توزیع‌شده را پاک نمی‌کند).
3. **مدل‌های صوتی آفلاین:** یک‌بار از GitHub دانلود می‌شوند (صدای فارسی ~۱۳۰MB، شنیدن ~۲۰MB)؛
   سپس بدون اینترنت کار می‌کنند. اولین دانلود به اینترنت نیاز دارد.
4. **صدای ابری:** متن پاسخ را به سرویس می‌فرستد (رضایت لازم) و هزینه/محدودیت سرویس را دارد.
5. **نام مدل‌ها:** پیش‌فرض‌ها بر اساس نام‌های شناخته‌شدهٔ سرویس‌ها هستند (مثلاً DeepSeek
   `deepseek-chat`/`deepseek-reasoner`). دسترسی واقعی به مدل به حساب/کلید بستگی دارد؛ کاربر
   می‌تواند per-service مدل را override کند. تست اتصال درون‌برنامه دسترسی را تأیید می‌کند.
6. **گفتگوی زندهٔ صوتی:** از ASR آفلاین روی دستگاه یا SpeechRecognizer سیستم استفاده می‌کند؛
   حالت کاملاً hands-free ملاحظات باتری/هزینه دارد. توقف/ادامهٔ پخش از طریق Speaker موجود است.
7. **عملیات نوشتنی:** دستیار عمداً فقط‌خواندنی است. هر عملیات حساس آینده (حذف، ثبت سند، تغییر
   موجودی/فروش/مشتری) باید از لایهٔ رسمی + **تأیید صریح کاربر** بگذرد؛ هیچ نوشتن مستقیم توسط
   مدل اضافه نشد. این طراحی آگاهانه برای حفظ امنیت است.
8. **credentialهای SQL جاسازی‌شده:** یافتهٔ امنیتی بالا — نیازمند دور جداگانه.
9. **تست runtime روی دستگاه:** نیازمند دستگاه/امولاتور + کلید واقعی؛ در این محیط اجرا نشد.

## ۵. نحوهٔ استفاده (راهنمای کوتاه)
1. تنظیمات ← هوش مصنوعی ← «تغییر سرویس» ← سرویس اصلی را انتخاب کنید (پیش‌فرض GapGPT).
2. مدل و کلید API همان سرویس را وارد و «ذخیره مدل و کلید» را بزنید.
3. «آزمایش اتصال این سرویس» را بزنید؛ نشان وضعیت باید سبز شود.
4. ترتیب جایگزین‌ها را بچینید؛ برای هر جایگزین هم مدل/کلید جدا بدهید (روی نامش بزنید).
5. رضایت داده را روشن کنید و «اتصال و فعال‌سازی» را بزنید.
6. در «دستیار میلانو» بپرسید؛ پاسخ‌ها از دادهٔ زندهٔ فروشگاه + مدل انتخابی ساخته می‌شوند.
