# ورود کاربر آتیران + نقش‌ها (نسخه ۲۶)

بعد از فعال‌سازی و تنظیم اتصال، برنامه یک **صفحه ورود کاربر** نشان می‌دهد و هر نقش فقط بخش‌های مجاز خودش را می‌بیند. مدیر، مدیر فروش، انباردار و سایر کاربران سیستمی از `sys_users` احراز هویت می‌شوند؛ ورود ویزیتور مسیر جدا دارد: اعتبار ورود از ردیف `visitors` و مجوز/شناسهٔ سیستمی از پیوند `sys_vis` خوانده می‌شود.

## نام کاربری و رمز از کجا می‌آید؟

### کاربران سیستمی: `sys_users`

مدیر، مدیر فروش، انباردار و نقش‌های سیستمی از جدول `sys_users` وارد می‌شوند:

| ستون | کاربرد در ورود |
|---|---|
| `user_name` | نام کاربری |
| `user_password` | رمز باینری آتیران (`varbinary(50)`) |
| `user_id` | شناسه یکتای کاربر |
| `role_id` | نقش سیستمی؛ عنوان از `Roles`/`role` خوانده می‌شود |
| `active` / `IsLocked` | کنترل فعال/قفل بودن حساب |

### ویزیتورها: `visitors` + `sys_vis`

نام کاربری و رمز ویزیتور در `visitors.Username` و `visitors.Password` قرار دارد؛
وضعیت حساب از `visitors.active` و شناسه/نام نمایشی از همان ردیف خوانده می‌شود.
ورود ویزیتور **به جست‌وجوی `sys_users.user_name` وابسته نیست**.

جدول `sys_vis` جدول رمز نیست؛ در ساختار نمونهٔ آتیران، ستون‌های `SysID`، `shvis` و
`UserID` را دارد و به‌ترتیب به سیستم، ردیف ویزیتور و کاربر آتیران پیوند می‌دهد.
برنامه برای پذیرش ورود ویزیتور وجود پیوند یکتا و معتبر آن را در `sys_vis` بررسی
می‌کند و `UserID` مثبت همان پیوند را برای نشست/حسابرسی به کار می‌برد. اگر ردیف
`visitors` پیدا شود ولی دسترسی `sys_vis` وجود نداشته باشد یا به چند UserID برسد،
ورود رد می‌شود؛ نام یا شناسه از روی اسم حدس زده نمی‌شود.

رمز `visitors.Password` در مسیر مخصوص ویزیتور جداگانه بررسی می‌شود. پیام‌های خطا و
گزارش تشخیصی هیچ‌گاه خود رمز یا مقدار ذخیره‌شدهٔ آن را نمایش نمی‌دهند.
برای کاربرانی که ویزیتور نیستند، مسیر بالا جایگزین احراز هویت `sys_users` نمی‌شود.

## رمز واقعی آتیران (نسخه ۲۷ سخت‌گیرانه است)

آتیران رمز را به‌صورت **باینری اختصاصی** (`varbinary(50)`) ذخیره می‌کند و
الگوریتم آن را منتشر نکرده است. برنامه برای پذیرفتن **رمز واقعی**، همه
راه‌های استاندارد را امتحان می‌کند — بدون هیچ حدس و خطای کور:

1. **سمت سرور:** تابع استاندارد `pwdcompare()` (اگر آتیران از رمزنگاری
   خود SQL Server استفاده کرده باشد، با صفر دانش از الگوریتم تأیید می‌شود).
2. **سمت گوشی:** همه هش‌های استاندارد
   (MD5 / SHA-1 / SHA-224 / SHA-256 / SHA-384 / SHA-512 × چهار انکدینگ شامل
   ویندوز-۱۲۵۶، حالت خام و هگز) **به‌علاوه حالت‌های نمک‌دار با نام
   کاربری**. اگر آتیران از هرکدام استفاده کرده باشد، همان رمز واقعی
   بدون هیچ تنظیمی کار می‌کند.

همه این‌ها فقط خواندنی‌اند؛ چیزی در سرور تغییر نمی‌کند و حسابی قفل
نمی‌شود. در فاز ۱ **هیچ راه دیگری** (رمز اپ، ورود راه‌اندازی) درِ ورود
را باز نمی‌کند — فقط رمز واقعی آتیران.

اولین ورود حتماً آنلاین است (خواندن سطر کاربر از سرور)؛ بعد از آن،
چون بایت تأییدکننده ذخیره می‌شود، **همان رمز واقعی به‌صورت آفلاین هم**
کار می‌کند.

## اگر رمز واقعی و درست قبول نشد (مسیر کشف الگوریتم)

یعنی آتیران از الگوریتم کاملاً اختصاصی استفاده می‌کند. مسیر حل:

1. در آتیران یک **کاربر آزمایشی موقت** بسازید با رمز مشخص (مثلاً `1234`).
2. روی سرور فروشگاه اجرا کنید (فقط خواندنی):
   ```
   pip install pymssql
   python tools/probe_atiran.py --host IP --db DB --user U --password P --pw-dump TESTUSER
   ```
3. خروجی (طول + هگز ذخیره‌شده) را همراه رمز آزمایشی بدهید به:
   ```
   python tools/crack_probe.py --password 1234 --user TESTUSER --hex ...
   ```
   اگر فرمول استاندارد باشد، دستورالعمل دقیقش را چاپ می‌کند تا در
   برنامه قرار گیرد؛ اگر نه، همان خروجی را برای پشتیبانی آتیران
   بفرستید و **الگوریتم ساخت `user_password`** را بخواهید.
4. کاربر آزمایشی را **حذف** کنید.

## فازبندی انتشار (از نسخه ۲۷)

| فاز | چه کسی وارد می‌شود | وضعیت |
|---|---|---|
| فاز ۱ | مدیر (داشبورد و ابزارهای مدیریتی) | ✅ فعال |
| فاز ۲ | + انباردار (صفحه‌ها و عملیات انبار) | ✅ فعال |
| فاز ۳ | + ویزیتور (مشتری، کالا، فروش و مطالبات) | ✅ نسخهٔ ۳۶٫۲۸ |
| فاز ۴ | + مدیر فروش (تحلیل و گزارش‌های محدود فروش) | ✅ نسخهٔ ۳۶٫۲۹ |
| فازهای بعد | فروشنده، حسابدار، موزع و مودیان | 🔜 تا تکمیل مسیرهای اختصاصی |

تا باز شدن فاز هر نقش، ورود آن با پیام «نسخه … هنوز منتشر نشده است»
بسته است. هر فاز با یک تغییر مشخص و عمدی در کد (`AtiranAuth.phaseOpen`)
باز می‌شود — هیچ نقشی تصادفی باز نمی‌ماند.

رمز ۴ رقمی اپ و قفل نقش در بخش «کاربران» از فاز ۲ به بعد برای
نسخه‌های هر نقش به کار می‌روند؛ در فاز ۱ فقط نقش «خودکار» برای تشخیص
مدیر مهم است.

## نقش‌ها چه می‌بینند؟

| نقش | صفحه شروع | بخش‌ها |
|---|---|---|
| مدیر مجموعه | خانه | همه |
| مدیر فروش | خانه | خانه، فروش، مشتریان، کالاها، ویزیتورها، داشبورد تحلیلی، گزارش‌های فروش، مطالبات، جستجو، صوتی، بیشتر |
| فروشنده | خانه | خانه، فروش، خرید، مشتریان، کالاها، ویزیتورها، چک‌ها، مطالبات، صندوق، دریافت/پرداخت، جستجو، صوتی، بیشتر |
| حسابدار | خانه | خانه، مشتریان، چک‌ها، مطالبات، صندوق، دریافت/پرداخت، گزارش‌ها، جستجو، صوتی، بیشتر |
| ویزیتور | مشتریان | خانه، مشتریان، کالاها، فروش، مطالبات، جستجو، صوتی، بیشتر |
| موزع | فروش | خانه، فروش، مشتریان، کالاها، چک‌ها، مطالبات، صندوق، جستجو، صوتی، بیشتر |
| انباردار | کالاها | خانه، کالاها، خرید، جستجو، صوتی، بیشتر |
| مودیان | فروش | خانه، فروش، مشتریان، گزارش‌ها، جستجو، صوتی، بیشتر |

نام کاربر واردشده همیشه با نشان 👤 بالای صفحه دیده می‌شود؛ با لمس آن
می‌توان خارج شد، کاربر را عوض کرد (مدیر: میان‌بر تعیین رمز کاربران).

## خاموش کردن، خروج، موارد خاص

- **خاموش کردن ورود:** مدیر از «تنظیمات » ورود کاربر آتیران» می‌تواند
  صفحه ورود را خاموش کند (فروشگاه‌های تک‌نفره).
- **خروج:** از نشان 👤 بالای صفحه یا تنظیمات؛ نشست به‌هم می‌خورد و
  ورود بعدی دوباره نام کاربری می‌خواهد.
- **«مرا به خاطر بسپار»:** روشن = ۳۰ روز، خاموش = ۱۲ ساعت. نشست
  راه‌اندازی مدیر فقط ۱۲ ساعت اعتبار دارد.
- **جدول ورود غایب یا غیرقابل‌خواندن:** ورود بدون احراز هویت باز نمی‌شود؛ برنامه خطا می‌دهد. برای کاربران سیستمی `sys_users` و برای ویزیتورها `visitors` و پیوند `sys_vis` لازم است.
- **فقط خواندنی:** ورود هیچ‌چیز در آتیران نمی‌نویسد (نه `IsLoggedIn`،
  نه `LoginDetails`، نه رمز). رمزهای اپ فقط در گوشی‌اند.
- **انتخاب‌گر قدیمی نقش‌ها:** وقتی ورود آتیران فعال است، نقش از آتیران
  می‌آید و انتخاب‌گر دستی کنار می‌رود؛ با خاموش کردن ورود، رفتار قبلی
  برمی‌گردد.

برای کمک به تنظیم دقیق نقش‌ها، روی سرور فروشگاه این را اجرا کنید
(فقط خواندنی، هیچ رمزی چاپ نمی‌کند) و خروجی را بفرستید:

```
pip install pymssql
python tools/probe_atiran.py --host IP --db DB --user U --password P --auth-dump
```
