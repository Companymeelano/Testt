# ورود کاربر آتیران + نقش‌ها (نسخه ۲۶)

بعد از فعال‌سازی و تنظیم اتصال، برنامه یک **صفحه ورود کاربر** نشان می‌دهد:
هر نفر با **نام کاربری آتیران خودش** وارد می‌شود و فقط **بخش‌های نقش خودش**
را می‌بیند. یک برنامه کامل، چهار نسخه (ویزیتور، موزع، انباردار، مودیان) به‌علاوه
مدیر، فروشنده و حسابدار — تشخیص همه از روی کاربر و نقش آتیران است.

## نام کاربری و رمز از کجا می‌آید؟

از جدول خود آتیران، `sys_users`:

| ستون | کاربرد در ورود |
|---|---|
| `user_name` | نام کاربری که تایپ می‌شود |
| `user_password` | رمز (باینری، `varbinary(50)`) |
| `user_id` | شناسه یکتای کاربر |
| `role_id` | نقش (نام آن از جدول `Roles`/`role` خوانده می‌شود) |
| `active` / `IsLocked` | حساب غیرفعال یا قفل، اجازه ورود ندارد |
| `user_fname` / `user_lname` / `phone` | نام نمایشی و تلفن |

نام نقش آتیران با کلیدواژه فارسی/انگلیسی به نقش اپ تبدیل می‌شود
(مدیر، حساب، انبار، ویزیتور، موزع/توزیع/راننده، مودی/مالیات، فروش).
اگر نامی شناخته نشد، نقش میانی **فروشنده** می‌گیرد و مدیر از بخش
«کاربران» نقش دقیق را دستی قفل می‌کند (در ورود بعدی اعمال می‌شود).

## رمز: دو لایه صادقانه (چرا؟)

آتیران رمز را به‌صورت **باینری اختصاصی** ذخیره می‌کند و الگوریتم آن را
منتشر نکرده است؛ پس برنامه بدون حدس و خطا، دو لایه دارد:

1. **تلاش هوشمند (آنلاین):** رمز تایپ‌شده با همه حالت‌های استاندارد
   (MD5 / SHA-1 / SHA-224 / SHA-256 / SHA-384 × سه انکدینگ، به‌علاوه
   حالت خام و هگز) با بایت ذخیره‌شده مقایسه می‌شود. اگر آتیران از هش
   استاندارد استفاده کرده باشد، **همان رمز آتیران بدون هیچ تنظیمی**
   کار می‌کند. این مقایسه فقط خواندنی است؛ چیزی در سرور تغییر نمی‌کند
   و حسابی قفل نمی‌شود.
2. **رمز ۴ رقمی اپ (آنلاین و آفلاین):** مدیر از بخش «کاربران» روی سطر
   هر کاربر، «تغییر» رمز را می‌زند و یک رمز ۴ رقمی تعیین می‌کند. این رمز
   فقط در گوشی (هش‌شده) نگه داشته می‌شود و **بدون اینترنت هم ورود**
   را باز می‌کند.

اولین ورود هر کاربر حتماً آنلاین است (خواندن سطر کاربر از سرور)؛
بعد از آن، ورود آفلاین با رمز اپ ممکن است.

## راه‌اندازی اول (مدیر)

1. مدیر «🛠 ورود راه‌اندازی مدیر» را می‌زند و رمز نقش مدیر را وارد
   می‌کند (پیش‌فرض `1234` — حتماً عوض شود).
2. وارد بخش «کاربران» می‌شود؛ روی سطر هر کاربر: تعیین رمز ورود،
   قفل نقش در اپ، و اتصال پرسنلی (کد ویزیتور/انبار برای شخصی‌سازی بعدی).
3. از این به بعد هر کاربر با نام کاربری خودش + رمز آتیران (یا رمز اپ) وارد می‌شود.

## نقش‌ها چه می‌بینند؟

| نقش | صفحه شروع | بخش‌ها |
|---|---|---|
| مدیر | خانه | همه |
| فروشنده | خانه | خانه، فروش، خرید، مشتریان، کالاها، ویزیتورها، چک‌ها، مطالبات، صندوق، دریافت/پرداخت، جستجو، صوتی، بیشتر |
| حسابدار | خانه | خانه، مشتریان، چک‌ها، مطالبات، صندوق، دریافت/پرداخت، گزارش‌ها، جستجو، صوتی، بیشتر |
| ویزیتور | مشتریان | خانه، مشتریان، کالاها، فروش، مطالبات، جستجو، صوتی، بیشتر |
| موزع | فروش | خانه، فروش، مشتریان، کالاها، چک‌ها، مطالبات، صندوق، جستجو، صوتی، بیشتر |
| انباردار | کالاها | خانه، کالاها، خرید، جستجو، صوتی، بیشتر |
| مودیان | فروش | خانه، فروش، مشتریان، گزارش‌ها، جستجو، صوتی، بیشتر |

نام کاربر واردشده همیشه با نشان 👤 بالای صفحه دیده می‌شود؛ با لمس آن
می‌توان خارج شد، کاربر را عوض کرد (مدیر: میان‌بر تعیین رمز کاربران).

## خاموش کردن، خروج، موارد خاص

- **خاموش کردن ورود:** مدیر از «تنظیمات » ورود کاربر آتیران» می‌تواند
  صفحه ورود را خاموش کند (فروشگاه‌های تک‌نفره).
- **خروج:** از نشان 👤 بالای صفحه یا تنظیمات؛ نشست به‌هم می‌خورد و
  ورود بعدی دوباره نام کاربری می‌خواهد.
- **«مرا به خاطر بسپار»:** روشن = ۳۰ روز، خاموش = ۱۲ ساعت. نشست
  راه‌اندازی مدیر فقط ۱۲ ساعت اعتبار دارد.
- **دیتابیس بدون `sys_users`:** برنامه کاربر را پشت صفحه ورود گیر
  نمی‌اندازد؛ با یک پیام، بدون ورود وارد می‌شود.
- **فقط خواندنی:** ورود هیچ‌چیز در آتیران نمی‌نویسد (نه `IsLoggedIn`،
  نه `LoginDetails`، نه رمز). رمزهای اپ فقط در گوشی‌اند.
- **انتخاب‌گر قدیمی نقش‌ها:** وقتی ورود آتیران فعال است، نقش از آتیران
  می‌آید و انتخاب‌گر دستی کنار می‌رود؛ با خاموش کردن ورود، رفتار قبلی
  برمی‌گردد.

## اگر رمز آتیران هیچ کاربری قبول نشد

یعنی آتیران از الگوریتم اختصاصی استفاده می‌کند. راه‌حل دائمی: از
پشتیبانی آتیران **الگوریتم ساخت `user_password`** (یا یک نمونه رمز
به‌همراه بایت ذخیره‌شده‌اش) بگیرید و به توسعه‌دهنده بدهید تا لایه اول
دقیق شود. تا آن روز، رمزهای ۴ رقمی اپ بدون مشکل کار می‌کنند.

برای کمک به تنظیم دقیق نقش‌ها، روی سرور فروشگاه این را اجرا کنید
(فقط خواندنی، هیچ رمزی چاپ نمی‌کند) و خروجی را بفرستید:

```
pip install pymssql
python tools/probe_atiran.py --host IP --db DB --user U --password P --auth-dump
```
