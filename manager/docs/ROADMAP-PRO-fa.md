# نقشهٔ راه نسخهٔ بسیار حرفه‌ای — اندروید و ویندوز (۱۴۰۵)

> خواستهٔ کاربر: «پیشنهادهای خودت را برای تکمیل این پروژه در نسخهٔ اندروید و ویندوز برای رسیدن به نسخهٔ بسیار حرفه‌ای».  
> طبق بررسی مخزن، **کد ویندوزی در پروژه وجود ندارد**؛ بخش «ویندوز» یک **طراحی از صفر** است که با زیرساخت موجود (دیتابیس آتیران، کدک لایسنس، updater امضاشده) هم‌ساز باشد.  
> گزارش بازبینی کد: `docs/REVIEW-1405-fa.md`

# بخش الف — اندروید

## ۳.۱ امنیت (نسخهٔ v37)

| اولویت | پیشنهاد | توضیح |
| --- | --- | --- |
| 🔴 | **TLS اختیاری برای WAN** | اکنون `network_security_config` برای LAN باز است (ضروری). افزودن «پروفایل WAN فقط-TLS»: وقتی اتصال از طریق `wan()`/`findWan()` است، فقط HTTPS/تعاریض TLS مجاز باشد؛ LAN همچنان cleartext. |
| 🔴 | **حداقل امتیاز ورود SQL** | ساخت «لاگین فقط-خواندنی» برای کارت‌های گزارش/داشبورد و جدا کردن نوشتن انبار/فاکتور (هماهنگ با بند «طرح ورود نقش‌محور» `docs/ACCESS_VISITOR_FIX_FA.md`). |
| 🟡 | **R8/ProGuard برای release** | فعلاً debug APK توزیع می‌شود. release با minify + حذف نام‌های Diag و خطاهای verbose. |
| 🟡 | **گزارش خرابی خودمیزبان** | ارسال استثناها به یک endpoint خودی (بدون دادهٔ مشتری/قیمت) — جایگزین Firebase برای حفظ حریم داده‌های فروشگاهی. |
| 🟢 | سنجش روت/شبیه‌ساز (Play Integrity در توزیع مارکتی) | فقط برای توزیع بازار؛ نسخهٔ مستقل فعلی نیاز ندارد. |

## ۳.۲ محصول و تجربهٔ کاربری

1. **«خروجی دفتر لایسنس»** در اپ admin: خروجی رمزگذاری‌شده (همان کدک `License.java`) از دفتر صدور + واردسازی روی دستگاه جدید — جایگزین بکاپ سیستم‌عامل (که با allowBackup=false بسته شد).
2. **چاپگر حرارتی ESC/POS**: افزودن ماژول چاپ فاکتور/رسید بلوتوثی — پرتقاضاترین قابلیت نسخه‌های فروشگاهی.
3. **پرداخت/دریافت QR-محور**: نمایش شبا/QR پرداخت روی فاکتور (الگوی استاندارد بازار ایران).
4. **حالت آفلاین کامل فروش**: `CacheStore` اکنون برای صورت‌حساب‌هاست؛ گسترش به کاتالوگ کالا/مشتری + صف ارسال هنگام اتصال.
5. **Widget و هشدار زنگ**: آیکن هشدار فعلی زنگ است؛ افزودن «هشدار سررسید چک» با لرزش/صدای قابل تنظیم.
6. **اتاق فرمان ویزیتور**: همگام‌سازی هدف‌های `vis_goals` و نمایش «فاصله تا هدف» در پروفایل بازرگان (زیرساخت `CommandRoomActivity` آماده است).
7. **بایگانی اسناد**: پیوست عکس/فایل به فاکتور و چک (ستون‌های `TableChanges`/`Log` زیرساختش هستند).

## ۳.۳ معماری و کیفیت کد

1. **یخ‌زدن/جداکردن `app/` ریشه**: `MainActivity` با ~۳۰ هزار خط میراثی است. توصیه: اعلام «legacy»، جلوگیری از رشد بیشتر، و انتقال هر قابلیت جدید فقط به `manager/`. (اسکن این دور: پرچم‌های آن عمدتاً دروغ‌مثبت بودند؛ ریسک اصلی نگهداری است نه امنیت.)
2. **تفکیک لایهٔ ارائه**: صفحه‌های `screens/` هنوز مستقیم کوئری می‌زنند؛ معرفی Presenter/ViewModel نازک برای تست‌پذیری (الگوی `HeadquartersModel` را به بقیه تعمیم دهید).
3. **پوشش تست**: افزودن تست برای `Jalali` (تبدیل تاریخ/parse)، `Money`/`PersianNumbers`، `PinHash` (legacy→v2)، `VisitorPricePolicy` (گروه‌های ۱..۵) — این‌ها منطق خالص‌اند و بدون ابزار UI تست می‌شوند.
4. **CI**: ماتریس build برای هر دو اپ (`manager`، `admin`) + اجرای `verify_all` در CI (هماهنگ با بند ۵ سند `ACCESS_VISITOR_FIX_FA.md`).
5. **مستندسازی SQL**: خروجی خودکار «نقشهٔ ستون‌ها» از `Meta.must` + `sample-schema.json` به‌صورت HTML برای تیم فروش/پشتیبانی.

## ۳.۴ عملیات انتشار

- کانال‌های بتا/پایدار در updater (همین حالا `release-manager` + `version.json` MAC دارد): افزودن فیلد `channel`.
- یادداشت انتشار خودکار (generate از commitها) در `dist/`.
- برنامهٔ پشتیبانی: SLA پاسخ، کانال ارتباط، و «بستهٔ عیب‌یابی» یک‌کلیکی (لاگ Diag + اطلاعات نسخه — بدون دادهٔ مشتری).

# بخش ب — ویندوز (طراحی از صفر)

## ۳.۵ انتخاب پشتهٔ فنی

| لایه | انتخاب پیشنهادی | دلیل |
| --- | --- | --- |
| فریم‌ورک | **.NET 8 + WPF** (یا Avalonia اگر لینوکس/مک هم خواستید) | بلوغ، RTL خوب با Vazirmatn/وزیرمتن، دسترسی مستقیم به SQL Server |
| دسترسی به داده | **Dapper + Microsoft.Data.SqlClient** | SQL همان کوئری‌های اثبات‌شدهٔ `MasterQueries/MoneyQueries` با کمترین هزینهٔ بازنویسی |
| گزارش/چاپ | **QuestPDF** (فارسی RTL) یا FastReport | فاکتور/رسید/دفتر قرض/چک |
| ذخیرهٔ رمزها | **DPAPI (CurrentUser)** + گزینهٔ Azure Key Vault | معادل Keystore اندروید |
| توزیع | نصب‌کنندهٔ امضاشده (MSIX یا Inno Setup) + همان `version.json` امضاشده برای updater | هم‌سازی کامل با کانال انتشار اندروید |

## ۳.۶ معماری

```
MeelanoDesk/
├── MeelanoDesk.Core        # منطق خالص: Jalali، Money/PersianNumbers، PricePolicy، کدک لایسنس (پورت License.java)
├── MeelanoDesk.Data        # Dapper + متا (Meta.colFlex)، Repo، CacheStore معادل
├── MeelanoDesk.App         # WPF (MVVM): Shell/Navigation، پوستهٔ طلایی/آجیلی (همان تم‌ها)
├── MeelanoDesk.Modules/
│   ├── Sales               # فاکتور/برگشتی/قیمت‌گذاری نقش‌محور (همان سیاست DefaultPriceGrp/forosh1..5)
│   ├── Customers           # دفتر مشتری/ویزیتور + مسیرها (masir)
│   ├── Cheques             # چک‌های دریافتی/پرداختی + سررسید/هشدار
│   ├── Inventory           # موجودی/انبارها/گردش (inventory_anbars)
│   ├── ManagerBoard        # داشبورد مدیر (KPI، روند ۱۴ روزه، مقایسهٔ امروز/دیروز — همان چیدمان اندروید)
│   ├── CommandRoom         # اتاق فرمان ویزیتور (همگام با دیتابیس مشترک)
│   └── License             # فعال‌سازی/دفتر صدور + SMS-gateway اختیاری
└── MeelanoDesk.Updater     # دانلود + راستی‌آزمایی sha256 + HMAC (پورت مستقیم License.updateMac)
```

**نکتهٔ کلیدی هم‌افزایی:** ویندوز و اندروید روی **یک دیتابیس آتیران** کار می‌کنند؛ لایهٔ SQL باید همان «نگاشت نام‌های منعطف ستون» (`Meta.colFlex`) را داشته باشد تا تفاوت نام‌گذاری نسخه‌های مختلف آتیران را ببلعد. بهترین راه: **تولید خودکار کلاس‌های داده از `sample-schema.json`** (همان ماشهٔ audit) برای هر دو پلتفرم.

## ۳.۷ هم‌سازی با اجزای موجود مخزن

| جزء موجود (جاوا/پایتون) | معادل ویندوز |
| --- | --- |
| `licensing/License.java` (S1/S2/S3 + کدک ۲۴ نویسه‌ای Crockford) | پورت مستقیم به C# — **همان کلیدها** تا لایسنس‌های صادرشده معتبر بمانند |
| `License.updateMac` + `tools/make_version.py` (HMAC نسخه) | همان طرح برای `version.json` ویندوز — یک سرور انتشار، دو کلاینت |
| `manager/tools/probe_atiran.py` | همان ابزار برای پیش‌بررسی دیتابیس مشتری (قابل اجرا روی ویندوز) |
| `AtiranAuth` (MD5/SHA-1 legacy) | پورت دقیق همان الگوریتم‌ها — **بدون تغییر**؛ فقط با دیتابیس هم‌ساز می‌ماند |
| `PinHash` (PBKDF2 v2 + مهاجرت legacy) | پورت مستقیم؛ فرمت ذخیره یکسان تا ابزارهای پشتیبانی مشترک بمانند |
| `Meta.must` / `sample-schema.json` | منبع واحد تولید کد داده برای هر دو پلتفرم |

## ۳.۸ نقشهٔ راه مرحله‌ای ویندوز

| فاز | محتوا | خروجی |
| --- | --- | --- |
| **۰ — بنیاد** (۲–۳ هفته) | راه‌اندازی راه‌حل، Core (Jalali/Money/License codec)، لایهٔ Data + متا، اتصال به دیتابیس نمونه، تست واحد | هستهٔ سبز + اتصال زنده |
| **۱ — هستهٔ فروش** (۴–۶ هفته) | ماژول Sales/Customers/Cheques با سیاست قیمت نقش‌محور، فاکتور چاپی QuestPDF RTL | فروش روزانهٔ کامل روی ویندوز |
| **۲ — مدیریت** (۳–۴ هفته) | Inventory + ManagerBoard (همان KPIهای اندروید) + گزارش‌های تجمیعی | داشبورد مدیر |
| **۳ — لایسنس و انتشار** (۲ هفته) | ماژول License + Updater (هم‌ساز با کانال اندروید) + نصب‌کنندهٔ امضاشده | نسخهٔ قابل توزیع |
| **۴ — اتاق فرمان و همگام** (۲–۳ هفته) | CommandRoom + همگام‌سازی اهداف ویزیتور | یکپارچگی با اپ ویزیتور |
| **۵ — صیقل** (پیوسته) | تم‌های طلایی/آجیلی (همان زبان بصری)، RTL کامل، دسترس‌پذیری، پرفورمنس، مستندسازی کاربر | نسخهٔ حرفه‌ای نهایی |

## ۳.۹ امنیت ویندوز

- رمزهای اتصال SQL در **DPAPI** (نه فایل متنی)؛ گزینهٔ «لاگین ویندوز/Active Directory» برای فروشگاه‌های دامنه‌دار.
- **امضای کد** برای نصب‌کننده و updater (همان زنجیرهٔ اعتماد اندروید).
- قفل برنامه با همان `PinHash` + **Windows Hello** (اختیاری).
- لاگ ممیزی عملیات حساس (حذف فاکتور/تغییر قیمت) — معادل `TableChanges`/`Log` آتیران.
