# برنامهٔ واحد با نقش‌های آتیران — «نسخهٔ مدیر» (۱۴۰۵)

> یک APK، همهٔ بخش‌ها؛ ورود با نام‌کاربری‌های سیستم آتیران؛ با تغییر نقش هر شخص فقط آیتم‌های همان نقش نمایش داده می‌شود.  
> پیشینهٔ فنی: `docs/ACCESS_VISITOR_FIX_FA.md` • بازبینی کد: `docs/REVIEW-1405-fa.md`

---

## ۱. اصل کار: یک برنامه، نسخه‌های نقش‌محور

- **یک APK** به‌نام «میلانو» (بستهٔ `ir.meelano.manager`) شامل **همهٔ ۳۴ بخش «اتاق فرمان»** در ۶ گروه: مدیریت روزانه و فروش، مالی و خزانه، کالا و عملیات انبار، تحلیل و گزارش، دستیار و ابزارهای هوشمند، مدیریت سیستم.
- **ورود فقط با حساب آتیران**: نام‌کاربری/رمز همان `sys_users` آتیران؛ نقش از **نام نقش همان کاربر در آتیران** خوانده و نگاشت می‌شود.
- **«نسخهٔ مدیر»**: نقش «مدیر» به **همهٔ بخش‌ها** دسترسی کامل دارد (تست `RoleVisibilityTest` این را برای هر ۳۴ بخش تضمین می‌کند).
- **ویزیتورها**: با ورود حساب ویزیتور، فقط «فروش میدانی» خودشان (مشتریان من، کالا و نرخ‌ها، ثبت ویزیت، پیش‌فاکتور، سفارش‌های من، دریافت وجه، گزارش روزانه) نمایش داده می‌شود — با دادهٔ همان حساب (`sys_vis`).

## ۲. نگاشت نقش آتیران → نقش برنامه

نگاشت خودکار از **نام نقش کاربر در آتیران** (`AtiranAuth.mapRole`) — حروف عربی/فارسی نرمال می‌شوند:

| نام نقش در آتیران (نمونه) | نقش برنامه | چه می‌بیند |
| --- | --- | --- |
| مدیر، admin، مدیر مجموعه | **مدیر مجموعه** | همهٔ ۳۴ بخش + اتاق فرمان کامل |
| مدیر فروش، سرپرست فروش | مدیر فروش | داشبورد فروش، عملکرد ویزیتورها، گزارش‌های فروش |
| فروشنده، فروش | فروشنده | فروش، خرید، مشتریان، کالاها، چک‌ها |
| حسابدار، حساب | حسابدار | چک‌ها، مطالبات، دریافت/پرداخت، گزارش‌های مالی |
| انباردار، انبار | انباردار | میزکار انبار، تحویل، رسید، شمارش، کالاها |
| ویزیتور، بازاریاب | ویزیتور | فقط فروش میدانی خودش |
| موزع، پخش، راننده | موزع | تحویل، مشتریان، مطالبات |
| مودیان، مالیات | مودیان | فاکتورها و گزارش مالیاتی |
| (نام ناشناخته) | فروشنده | قابل تغییر توسط مدیر |

## ۳. «فقط آیتم‌های مختص به خودشان»

| لایه | رفتار |
| --- | --- |
| **نوار پایین** | تب‌های هر نقش فقط مقاصد مجاز همان نقش (`RoleStore.tabsFor`) |
| **«اتاق فرمان» (همه بخش‌ها)** | فهرست گروه‌بندی‌شده؛ هر ورودی که برای نقش مجاز نیست نمایش داده/باز نمی‌شود |
| **نوار ابزار بالا** | «جستجو» و «تنظیمات» فقط برای نقش‌های مجاز آن بخش |
| **داشبورد** | تراشه‌های «گزارش ›»، دکمه‌های «فروش ›/دریافت‌ها ›»، کارت‌های خرید/فروش/پرداخت/دریافت و هشدارها فقط وقتی مقصدشان برای نقش مجاز باشد |
| **ناوبری (مرکزی)** | `MainActivity.nav()` برای هر مقصد `RoleStore.allowed` را می‌سنجد؛ موارد غیرمجاز با پیام «محدودیت نقش» بسته می‌مانند |

> اجرای دو لایه: **نمایش** (فقط آیتم‌های خودت) + **کنترل** (قفل ناوبری مرکزی). تغییر نقش هر شخص ⇒ بلافاصله مجموعهٔ آیتم‌هایش عوض می‌شود.

## ۴. تغییر نقش هر شخص توسط مدیر

در بخش **«کاربران»** (فقط نقش مدیر): فهرست کاربران آتیران با نقش خودکارِ نگاشت‌شده؛ مدیر می‌تواند برای هر شخص **نقش جایگزین** انتخاب کند (مثلاً حساب «فروش» را «مدیر فروش» کند). نگاشت خودکار دست‌نخورده می‌ماند و با «حذف جایگزین» به حالت خودکار برمی‌گردد.

- نقش نشست = `effectiveRole` = نقش جایگزین (در صورت وجود) یا نقش خودکارِ نگاشت‌شده از آتیران.
- با ورود کاربر، نقش از آتیران می‌آید؛ تعویض دستی نقش فقط در حالت بدون نشست (نقش‌گذاری قدیمی) ممکن است.

## ۵. تغییرات این دور (v36.36.0)

1. **نوار ابزار نقش‌آگاه**: «جستجو»/«تنظیمات» برای نقش‌های فاقد دسترسی پنهان شد.
2. **داشبورد نقش‌آگاه**: تراشه‌های گزارش، دکمه‌های اقدام، کارت‌های KPI روز (خرید/فروش/پرداخت/دریافت) و هشدارها فقط برای مقاصد مجاز نقش نمایش داده می‌شوند (چیدمان داشبورد مدیر بدون تغییر).
3. **تست تضمینی `RoleVisibilityTest`**: مدیر به هر ۳۴ بخش می‌رسد؛ ویزیتور فقط فضای خودش؛ تب‌های هر نقش داخل دسترسی‌هایش؛ فیلتر ابزارها؛ نگاشت نقش‌های آتیران.
4. **سخت‌سازی PIN نقش‌ها**: هش PBKDF2 با salt تصادفی + مهاجرت شفاف از هش قدیمی (مثل قفل برنامه و PIN کاربران).

## ۶. چک‌لیست استقرار برای فروشگاه

1. در آتیران، برای هر شخص **نام نقش** درست را تنظیم کنید («مدیر» برای مدیر، «ویزیتور» برای ویزیتورها — جدول بخش ۲).
2. برنامه را نصب و با حساب آتیران وارد شوید؛ نسخهٔ نقش در «حساب کاربری» دیده می‌شود.
3. در صورت نیاز، نقش جایگزین هر شخص را از «کاربران» تنظیم کنید.
4. برای نقش «مدیر مجموعه» حتماً PIN قفل برنامه/نقش را تغییر دهید.
