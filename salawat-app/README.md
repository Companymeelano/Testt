# صلوات برای امام زمان (عج)

برنامهٔ شمارش صلوات با محوریت **سلامت و ظهور امام زمان (عج)**، شامل:

- **صفحهٔ وب** (`web/`): شمارش با دکمه و عدد دلخواه، انتخاب نیت، کارنامهٔ شخصی و آمار جمعی روزانه با نوار هدف.
- **ربات روبیکا** (`backend/rubika_bot.py`): همان شمارش از داخل پیام خصوصی روبیکا، با دکمه‌های شیشه‌ای.
- **API** (`backend/main.py`، FastAPI) که هم وب و هم داده‌ها را سرویس می‌دهد.

ساخته‌شده با **پایتون ۳.۱۱+** و **SQLite** (بدون سرور دیتابیس جدا).

## نیت‌ها
| کد | نیت |
|---|---|
| `health` | سلامتی و طول عمر امام زمان (عج) — نیت پیش‌فرض |
| `zohoor` | تعجیل در ظهور و فرج |
| `yari` | یاری و آمادگی منتظران |

## راه‌اندازی محلی

```bash
cd salawat-app
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

# وب و API (http://localhost:8000)
uvicorn backend.main:app --host 0.0.0.0 --port 8000

# ربات روبیکا (در فرایند جداگانه؛ توکن را از پنل ربات روبیکا بگیرید)
export RUBIKA_BOT_TOKEN="..."
python -m backend.rubika_bot
```

### متغیرهای محیطی
| نام | توضیح | پیش‌فرض |
|---|---|---|
| `SALAWAT_DB` | مسیر فایل SQLite | `data/salawat.db` |
| `SALAWAT_DAILY_CAP` | سقف شمارش روزانهٔ هر کاربر | `20000` |
| `SALAWAT_ADMIN_KEY` | کلید تنظیم هدف روزانه (`POST /api/admin/goal` با هدر `X-Admin-Key`) | خالی (غیرفعال) |
| `RUBIKA_BOT_TOKEN` | توکن ربات روبیکا | — |
| `LOG_LEVEL` | سطح لاگ ربات (`DEBUG` برای دیدن فیلدهای به‌روزرسانی) | `INFO` |

## وضعیت و نکات قبل از انتشار
- **ربات روبیکا** بر پایهٔ مستندات عمومی روبیکا (`https://botapi.rubika.ir/v3/<token>/<method>`) نوشته شده است. نام فیلدهای به‌روزرسانی (`new_message`، `inline_message`، `aux_data`) را **قبل از انتشار با یک پیام واقعی** تأیید کنید؛ آن‌ها فقط در `parse_update` هستند.
- محیط توسعه‌ای که این کد در آن ساخته شده به `botapi.rubika.ir` دسترسی ندارد؛ تست زندهٔ ربات باید از شبکه‌ای انجام شود که به روبیکا دسترسی دارد.
- **متن ادعیه و صلوات** (در صفحه و ربات) باید پیش از انتشار توسط مرجع دینی بررسی و تأیید شود.
- داده‌ها ناشناس‌اند: کاربر فقط یک توکن تصادفی در مرورگر یا یک شناسهٔ چت روبیکا دارد؛ نام یا شماره ذخیره نمی‌شود.
- برای انتشار عمومی: HTTPS، پشتیبان‌گیری منظم از فایل SQLite، و در صورت رشد، انتقال به PostgreSQL.
